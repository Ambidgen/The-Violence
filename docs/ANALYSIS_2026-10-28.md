## 1. What the project is

A Godot 4 (4.7.2 primary, 4.4.1 supported, compatibility renderer) police-command game:
a deterministic close-quarters autobattler under a forty-week campaign in a fictional
rust-belt city. Three layers matter for planning:

| Layer | Where | Gate |
|---|---|---|
| Deterministic CQB simulation | `scripts/sim/` (world, brains, navigation, recorder) | `--range` tier, `determinism_test`, `brains_test`, `equip_test` |
| Campaign and run layer | `scripts/campaign/` (`campaign.gd`, `department.gd`, `politics.gd`, `rogue.gd`) | `rogue_test`, `dept_test`, `politics_test`, `city_integration_test` |

`scripts/campaign/rogue.gd` (1,200 lines) is the entire roguelike run layer: inheritance,

this cycle's work is.

## 3. Cycle 0.C — the duplicate procurement charge

### 3.1 The bug, and why the plan's first fix could not work

The 28 Oct playtest charged **$6,000** for plate carriers the armoury already held, in
**6 of 12 seeds** (`contracts` became `["plates","plates"]`).

`EA_TASKS` P0.C1 asks for a deal-time filter on contracts whose items are all stocked.
That filter **already existed** — `_open_contracts()` skipped any contract whose every
item was in `armory` — and it could not help, because of ordering:

```
on_week_start(week 1)   deals the doctrine draft (3 cards)
                        deals the procurement draft (3 contracts)   <- armoury: patrol stock
pick(doctrine = "plates")  stock(["plates"]), contracts += "plates"
                           ... and the procurement draft still offers "plates" for $6,000
pick(procurement = "plates")  charges, adds nothing, duplicates the contract id
```

The redundancy is created *after* the deal, so the fix has to run *after every stocking
change*, not only at deal time. That is a plan correction worth recording: P0.C2, not
P0.C1, is the fix; P0.C1 is the invariant the deal should maintain.

### 3.2 What was implemented (`scripts/campaign/rogue.gd`)

- **One predicate.** `contract_stocked(cid)` — true when every item the contract carries
  is in `armory`. Used by `_open_contracts()` (deal), `_revalidate_drafts()`, and the
  refusal in `pick()`. A contract with *some* new items still sells: breaching rounds
  arrive with a shotgun the armoury may already hold.
- **Revalidation after any stocking change** (`_revalidate_drafts()`), called from the
  end of `pick()` — which covers a doctrine pick and a signed contract — and from
  `apply()` — which covers a free contract granted by an offer or event. Each redundant
  card is replaced **within its tier**; if nothing is left to offer the card is dropped,
  and a draft with no cards is dropped, so the week cannot be blocked by a card that
  cannot be bought.
- **A separate RNG stream** for the replacement (`draft_rng`, seeded `seed × 9241 + 137`,
  saved as `draft_rng_state`). The desk's `rng` does not move, so the offers, events and
  later drafts a seed deals are unchanged by a re-deal. Without this, the DEBUG note in
  the plan ("if the same seed deals the same desk fails, the replacement consumed the
  main RNG") would have fired.
- **A guard in `pick()`** (P0.C3): a contract for stocked kit is refused with a line, no
  charge, and the draft still open. `from_data()` re-validates restored drafts, so a run
  saved between the inheritance and the contract is repaired on load — this is the path
  the playtest's own screenshot (`procurement-after-plates.jpg`) shows.
- **Board text**: "PROCUREMENT · %d contracts, sign one" reads the draft instead of
  claiming three.

### 3.3 The regression (P0.C4)

`tests/rogue_test.gd` now checks, for **seeds 1–12 × every inheritance × every contract
still offered afterwards**:

1. no card in the draft after the inheritance is fully stocked;
2. signing each remaining card charges **exactly** the contract's cost and adds **at
   least one** item (0 wasted purchases);
3. a re-dealt card leaves the desk's `rng` where it was and advances `draft_rng`;
4. the guard refuses a hand-planted redundant card with no charge and no closed draft;
5. a free military contract arriving mid-week (Kettering's armoured truck) stocks the
   armoury and leaves no stocked card behind, with the draft still open.

The 28 Oct `dup_probe.gd` (kept in `tests/results/playtest-2026-10-28-campaign/logs/`) is
folded in and no longer needs copying into `tests/`.

### 3.5 Residual risk

- The count of replaced cards depends on the deal, not on a fixture; if a future change
  makes the week-1 pool exclude `plates` entirely, the positive control (`redealt > 0`)
  fails and tells you the regression has gone quiet.
- `--matrix-seeds=12` costs ~150 campaign constructions. It ran inside the quick tier's
  budget; `--matrix-seeds=4` is available for a fast local loop.
- The suite does not render the refusal line or the new board label. `ui_walk.gd` uses
  seed 410255, which deals SMG rather than plates, so the walk's procurement step never
  sees a re-deal. A second walk seed that deals plates would close that gap — a natural
  addition to P3.C2.

## 4. Where the critical path really is (Phase 1)

Phase 0 is nearly closed; the product risk is unchanged and is all in Phase 1. Reading
the code confirms the plan's diagnosis rather than contradicting it:

- **The crowd cliff is real and mechanical.** `department.gd:771` sets
  `stress0 = min(0.3, trauma × 0.015)` (plus up to 0.05 for morale below 60);
  `world.gd` never decays `stress` below `stress0`; `misjudge_p()` (`world.gd:1290`)
  treats an officer as calm only at `stress < 0.2`, and calm is what makes the
  already-cleared-face rule return 0 instead of ×0.1 (`world.gd:1310-1317`). Trauma
  ≥ 13.4 therefore disables that rule permanently, which is exactly the measured
  cliff (0 civilians struck at trauma 10, 52 at 14). P1.B2's "calm relative to the
  officer's own floor" is the right shape of fix, and P1.B3's check-fire is the right
  defence in depth.
- **The economy and roster failures are policy-sensitive, which is why the harness comes
  first.** The three 28 Oct runs fail differently under different hiring and training
  choices (debt by week 5–10 with hiring; $369K unspent and 80 calls unattended without),
  so no single tuning change can be judged by eye. P1.A (four policies as code, one
  process per seed × policy, bands in report-only mode, a committed baseline) is the
  correct first move, and the plan's own cost estimate (≈7–10 h for 80 runs on two cores)
  matches what a 40-week headless run costs here.
- **Two simulation gates fail for real reasons, not for noise**: B1 (wolf brain hides
  less with the trait on) and B2/B3 (shield lets more rounds through; beanbags slow the
  arrest). They are scheduled for the Phase 1 rebaseline, correctly — changing them now
  would invalidate the fixture twice.
- **B4** (an intermittent 4.4.1 quick-tier failure seen on the first CI run) did not
  recur in this run or in the 0.A run; it stays a watch item, and the annotation change
  means the next occurrence names its suite.

## 5. Other observations worth acting on

1. **The roadmap's status table is stale** (§3 of `EARLY_ACCESS_ROADMAP.md`): CI is
   active, the duplicate is fixed, and the harnesses now fail honestly. It is the first
   document a reader opens; a one-line "as of cycle 0.C" note would stop it misinforming.
2. **`apply()` draws a free military contract from the desk's `rng`**
   (`rng.randi() % mil.size()`), so *accepting* an offer shifts every later deal. That is
   defensible — a choice should change the run — but it is not the "separate sub-stream"
   discipline that P0.C2 establishes, and it is worth a deliberate decision before the
   balance baseline is recorded (a policy that accepts offers will otherwise be measured
   against a different stream from one that declines).
3. **The refusal line is only visible after a click.** P3.B1 (print the reason under a
   disabled button) would have prevented this bug from being a trap at all; it remains
   the cheapest legibility fix in the plan.
4. **`tests/results/` is inside the test tree but not in `tools/run_tests.sh`'s paths.**
   The old `dup_probe.gd` and `ui_walk.gd` there are historical copies; folding the probe
   into `rogue_test` means there are now two definitions to keep apart. The directory is
   evidence, not code — worth saying so in its README.
5. **0.D can start immediately** and is independent of everything in Phase 1: the version
   line (1.3.x = Early Access, 2.0 = release), `LICENSE` + `THIRD_PARTY_NOTICES`, the
   Remotion licence decision (it gates P4.C), and the fixed `user://` name before Steam
   Cloud paths exist.
