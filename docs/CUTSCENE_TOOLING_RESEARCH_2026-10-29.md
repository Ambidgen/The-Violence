## 0. TL;DR — the answer in six lines (revised for the crayon style)

1. **Default answer: author cutscenes in-engine in Godot, in crayon.** `scripts/view/crayon.gd` already *is* the target renderer — seeded jitter (`rnd`/`jit`), hatching/charcoal cross-hatch, smudge, puddle/light-as-scribble, draw-on reveal, 8 fps boil, `GLYPHS` stroke lettering — and `scripts/view/proto/cutscene_view.gd` already proves the full cutscene form in it (hand-projected 3D crossroads, parallax camera creep, 170-person crowd, riot line, captions printed on, ending stamp). No external tool surveyed can match that style without first re-implementing this library. In-engine also gets live roster/ward/headline for free, is seekable/skippable, and adds zero Theora MB. Plugins **Phantom Camera** (camera) and **Dialogic 2 / Dialogue Manager** (dialogue/timeline) remain the recommended additions.
2. **External renderers are now on probation, not "proven".** The five `trailers/` cuts were all rejected by the owner (see Correction). Clean React/HTML/Canvas motion graphics — the natural output of Remotion, HyperFrames, Revideo, Motion Canvas — is precisely what failed. Any of them may still be used *only if* it first passes a crayon-fidelity spike: port ~6 primitives from `crayon.gd` (jittered stroke, gone-over-twice line, hatch, charcoal, boil stepped at 8 fps not smooth 30/60 fps easing, draw-on reveal) and reproduce a reference frame side-by-side. **Rough.js** (MIT, ~21.3k★, github.com/rough-stuff/rough — hand-drawn sketchy primitives for Canvas/SVG, last pushed Jul 2024) is the obvious accelerator for that port on the JS side; SVG `feTurbulence` displacement alone will not do it (it roughens edges but cannot boil, hatch or draw on).
3. **Ranking among external renderers flips under crayon.** Canvas-2D hosts (**Revideo / Motion Canvas**) map most directly onto `crayon.gd`'s immediate-mode `draw_*` calls; DOM/CSS hosts (HyperFrames/Remotion) fight you with smooth tweening, anti-aliased vector cleanliness and typeset text. HyperFrames keeps its Apache-2.0/agent-ergonomics edge, but its "natural look" is now a liability to be engineered away, not an asset.
4. **Blender + Grease Pencil rises** — it is genuinely hand-drawn media with a real camera, arguably the closest external relative of the crayon plates — still hero-sequence-only on cost.
5. **The agentic layer remains a workflow, not a product** (agent writes code → render → contact sheet → vision review → iterate; your `sheet.mjs` is the verify half). Do not adopt OpenMontage wholesale (AGPL-3.0) — steal its pipeline pattern. Agent *fluency* now means fluency in your stroke primitives, whichever language they're in.
6. **Reject generative video (Wan 2.x, HunyuanVideo, CogVideoX, LTX) outright** — if clean code-drawn output already failed the style bar, stochastic photoreal/AI footage fails it harder, plus non-determinism and no character consistency.

**Recommended combination (revised §7):** `Godot/crayon.gd in-engine cutscene layer (primary) + Phantom Camera & one dialogue plugin + the existing proto/cutscene_view.gd as reference implementation — external renderer (Revideo- or HyperFrames-flavoured) only behind a passed crayon-fidelity spike, for anything genuinely easier pre-rendered — Blender/Grease-Pencil spike only for a hero opening.`

## 3. Category B — Code animation libraries an agent composes *inside* a renderer

These are not Remotion replacements; they multiply whichever host (§2, §4 or Godot) you pick.

- **Rough.js** — github.com/rough-stuff/rough, MIT, ~21.3k★ (last pushed Jul 2024 — stable/finished rather than active; zero-dependency, small). Creates hand-drawn, sketchy Canvas/SVG graphics (jittered double-strokes, hachure fills). **The single most relevant JS library under the crayon style**: it is the off-the-shelf half of a `crayon.gd` port for any §2 host. It does not boil, draw-on or manage a palette — you supply stepped-frame re-randomisation (seeded!), reveal clipping and the VISUAL_OVERHAUL tokens. ★★★★★ as crayon-port accelerator.
- **Paper.js** — github.com/paperjs/paper.js, ~15.2k★, active. Full vector geometry (boolean ops, path smoothing) on Canvas. Useful if crayon shapes need geometry help; does not provide the hand-drawn look itself. ★★★
- **GSAP** (npm; free incl. formerly-paid plugins since Webflow acquisition — verify current terms before shipping) — timeline/easing engine inside HyperFrames; already in `trailers/package.json` (3.15.0). Agent writes it reliably — but its smooth interpolation must be deliberately degraded (stepped/quantised to the 8 fps boil, eased `steps()`) or it reads as slick motion graphics. ★★★★ with that caveat
- **PixiJS** — github.com/pixijs/pixijs, MIT, ~48.6k★, active. Fastest 2D WebGL renderer; would let a scene run dozens of crayon officers/vehicles (your `assets/crayon/` sprites) with particles/weather, rendered via headless Chromium frame capture or *live in a Godot Web export shell*. Complexity budget far beyond SVG. ★★★★ for a future "operation replay" scene type.
- **Three.js / React-Three-Fiber** — github.com/mrdoob/three.js, MIT, ~117k★. Only if you want true 3D camera moves over an extruded Port Carrick map (C1's skyline/wards in parallax 3D). Powerful, but invites style drift from flat ink. ★★★ for one hero shot.
- **p5.js** — github.com/processing/p5.js, LGPL-2.1, ~24.3k★. Already proved (`trailers/p5/`, `renders/05-radio-silence-p5.mp4`) for generative textures: rain, radio static, dispatch noise. Keep as texture/effects supplier, not scene host.
- **Manim (Community)** — github.com/ManimCommunity/manim, MIT, ~42k★, active. Python, LaTeX-free for your use. Unbeatable for animated diagrams: plan routes drawing themselves, ward choropleths, timeline/election maths. An agent writes Manim well; existing agent wrappers exist (e.g. `evlo-malik/manim-video-agent`, `paulnegz/manim-mcp`, MIT — alpha, treat as pattern not dependency). ★★★★ as a *supplier* of diagram plates composited in Remotion/HyperFrames, matching your C3 "plan" language.
- **Lottie / dotLottie** (airbnb/lottie-web, MIT, ~32k★) and **Rive** (rive-app runtimes, MIT) — excellent for small UI/icon motion and Godot has community Lottie/Rive paths, but both want a GUI-authored source file (After Effects / Rive editor). An agent cannot originate rich Lottie JSON happily. ★★ — consume only if a human designs assets.
- **Theatre.js** — github.com/theatre-js/theatre, Apache-2.0, ~12.8k★ but **last pushed Aug 2024**. Visual timeline on top of Three/HTML. Stale; skip.

## 4. Category C ⭐ — In-engine Godot cutscenes (the "complex" unlock)

**Why this category matters most for your request:** "Complex animated cutscenes" that know *which officer died, which ward, what the headline actually was* cannot be fully pre-rendered — your own slot system is an admission of that. In-engine scenes get all live state for free, at native resolution/aspect, seekable, skippable, branchable, and add **zero MB** of Theora. Your top-down maps, crayon sprites (`assets/crayon/{op,veh,fx,ui}`) and `scripts/view/crayon.gd` are already a cutscene stage waiting to be directed. An agent writes GDScript + `.tscn` text and `AnimationPlayer`/`Tween` code as fluently as JSX — and can verify with your existing headless Godot test harness, no Chromium/Theora round-trip.

## 5. Category D — Assembly, post & interchange (combination glue)

- **FFmpeg** (LGPL/GPL components; github.com/FFmpeg/FFmpeg mirror ~66k★) — already your load-bearing glue (loudness-normalise + libtheora transcode in `to_game*.sh`); also concat, mix SFX beds, burn captions, extract review frames. Indispensable under every stack.
- **MoviePy** — github.com/Zulko/moviepy, MIT, ~15.1k★, PyPI. Python compositing for an agent that thinks in Python (plate assembly, text overlays); slower/less precise than FFmpeg filters alone — use as orchestrator, render with FFmpeg.
- **Editly** — github.com/mifi/editly, MIT, ~5.6k★ (single maintainer, last push May 2025). Declarative JSON5 edit specs → FFmpeg. Good for trailer/social re-cuts of existing cutscenes; too coarse for originating ink scenes.
- **OpenTimelineIO** — github.com/AcademySoftwareFoundation/OpenTimelineIO, Apache-2.0, ~2.0k★. Timeline interchange if you ever round-trip between engines/editors. Overkill now; note for later.
- **OpenShot / Kdenlive (MLT)** — GUI editors, agent-hostile as authors, fine as human review/trim stations. Not part of an agentic pipeline.

## 6. Category E & F — Traditional animation authoring, and "AI video"

**E. Scriptable traditional tools (hero work only):**
- **Blender + Grease Pencil** (blender.org; GitHub mirror ~21k★; GPL tool, **your output is yours**) — `bpy` Python API, headless `blender -b -P scene.py`. The only surveyed tool offering 2D hand-drawn animation *inside* a 3D camera — Port Carrick skyline with real parallax in your crayon/ink line is achievable and fully agent-scriptable. Cost: heavyweight binary, long renders, a new skill surface. One hero opening/launch trailer: yes. Fourteen 7-second shorts: no.
- **OpenToonz** (github.com/opentoonz/opentoonz, BSD-style, ~7.9k★) and **Synfig** (github.com/synfig/synfig, GPL-3.0 tool, ~2.3k★) — real 2D animation studios (Ghibli heritage for OpenToonz) but GUI-first; file formats are XML an agent *can* generate, with a painful verify loop. Behind Blender for this brief.
- **Krita** (Python-scriptable, GPL tool) — worth noting for agent-generated painted plates/textures fed into §2/§4; not an animation host here.

**F. Generative video — surveyed and rejected for shipped cutscenes:**
Wan 2.x, Tencent HunyuanVideo, CogVideoX, LTX-Video, Open-Sora (GitHub; various community licences; open weights ≠ open-source pipeline) produce ≤~10 s clips with no cross-shot character consistency without per-character LoRA training, non-deterministic output, and heavy GPU cost [6](https://videodubber.ai/blogs/best-opensource-ai-video-generator-2026/). Every one of those failures is fatal against §1's determinism + exact-style + named-officer requirements. **Permitted use:** disposable mood/concept frames during pre-production (like the AI key art already disclosed in `trailers/README.md`), never in-game footage. ComfyUI (GPL) as image-plate generator sits in the same "concept only" bucket.

**Agentic orchestration (cross-cutting):**
- **OpenMontage** — github.com/calesthio/OpenMontage, **AGPL-3.0**, ~73k★, very active: 12 YAML pipelines, 100+ Python tools, agent "skills", self-review + checkpoint gates, renders via Remotion *or* HyperFrames + FFmpeg [7](https://github.com/calesthio/OpenMontage). It is the best public reference implementation of the loop you want — and AGPL + enormous surface for a proprietary game. **Mine it for patterns (pipeline YAML, reviewer gates, frame-extraction QA); do not vendor it.**
- **Remotion Agent Skills / HyperFrames agent skills / `iart-ai/motion-skills`** (GitHub) — installable skill packs teaching a coding agent each framework + a deliver-and-verify loop. Cheap to adopt, framework-aligned. Evaluate motion-skills before installing (third-party, scan any skill pack as untrusted code).
- **Manim agent wrappers** (`manim-video-agent`, `manim-mcp`) — same pattern for diagram scenes; alpha-quality, pattern-only.

## 7. Recommended combinations (revised for crayon)

### Stack 1 — Adopt as primary: in-engine crayon cutscenes
`Godot + scripts/view/crayon.gd (+ crayon_figures/props/plan painters) + Phantom Camera + Dialogue Manager (or Dialogic 2) — grown from scripts/view/proto/cutscene_view.gd`
- Formalise the prototype into a `CutscenePlayer` scene with the same contract as `scripts/ui/shorts.gd` (`play(key, props, on_done)`, skip on Space/click), driven by a small declarative beat script (JSON/GDScript data: shot, camera, actors, caption, SFX cue, trigger) that an agent authors and the engine stages — the in-engine analogue of `shorts/registry.js`, including live campaign props with no slot-overpaint hack.
- Reuse the baked-boil machinery (`tools/bake_crayon.gd`, 3-variant AnimatedTextures, SubViewport caching per VISUAL_OVERHAUL technical approach) for perf; keep the "Line boil" accessibility setting authoritative.
- Convert beats in value order: first any *new* cutscene; then S06/S12 (officer-specific), S11/Election (the prototype already *is* this scene); the C1–C4 opening last and most carefully.

### Stack 2 — Conditional: external pre-render, behind the crayon gate
`Revideo (preferred) or HyperFrames + Rough.js crayon layer + FFmpeg → Theora`, only for beats genuinely better pre-rendered (dense painterly plates, heavy compositing) and **only after §8 Spike 1 passes**. The registry/props/slots contract stays identical so `shorts.gd` doesn't care which side rendered a beat.

### Stack 3 — Hero only
`Blender + Grease Pencil (headless bpy)` for a future opening/launch centrepiece; captions/stamps composited in Stack 1 or 2. Timeboxed by §8 Spike 4.

### Not recommended
Treating any `trailers/` cut as a starting point (all rejected) · migrating scenes between JS engines before the crayon spike decides · OpenMontage/MotionForge/GDrama as dependencies · diffusion video in shipped footage · Lottie/Rive as agent authoring.

## 10. Can this stack be actuated purely through accessing the GitHub repo?

**Short answer: yes for Stack 1 (the recommended in-engine crayon stack) — with execution delegated to GitHub Actions — mostly for Stack 2, and no, not practically, for the Blender hero stack from an agent sandbox like this one. Nothing in the recommended stack requires a human-operated GUI, a local workstation, or a non-GitHub marketplace.** Checked 2026-10-29:

| Step | Pure-GitHub? | How / caveat |
|---|---|---|
| Author all cutscene code & data (GDScript, `.tscn`, shaders, beat-script JSON, captions) | ✅ | Plain text in the repo; an agent with repo write access creates/edits/commits it directly. The crayon painters (`crayon*.gd`, `assets/crayon/`) are already here. |
| Obtain the plugins (Phantom Camera, Dialogic 2 / Dialogue Manager — all MIT on GitHub) | ✅ | Clone/vendor their GitHub repos into `addons/` (subtree or plain copy + licence file), enable in `project.godot`, add `THIRD_PARTY_NOTICES`. The Godot AssetLib is *not* needed — every recommended plugin's canonical home is GitHub. |
| Obtain the engine | ⚠️ via CI, not via agent sandbox | Godot is *distributed* via `godotengine/godot` GitHub Releases, but the release asset 302-redirects to `objects.githubusercontent.com`. Probed from this sandbox: redirect not followable (0 bytes) — consistent with CHANGELOG's "no Godot binary could be run here". **GitHub-hosted Actions runners can download it** — and already do: `.github/workflows/ci.yml` fetches 4.7.2/4.4.1 and runs the headless suites on every `arena/**` push. So the loop is: agent pushes → Actions executes. |
| Run logic tests headless | ✅ today | Existing CI (above) + `tools/run_tests.sh` tiers. A cutscene beat harness (play beat, assert props/signals/skip) fits the existing `-s` GDScript pattern with no new infrastructure. |
| Render frames / contact sheets for visual review | ⚠️ needs one new CI job | `tests/proto_capture.gd` "needs a display" (it reads `get_viewport().get_texture()`; `--headless` uses a dummy RenderingServer and captures nothing). Fix is repo-only: a workflow job that installs Xvfb, runs `xvfb-run godot --path . -s res://tests/proto_capture.gd -- --which=cutscene …`, builds a contact sheet, and uploads it as an Actions artifact (or commits it under `tests/results/`, the pattern the balance/crowd jobs already use). **Built 2026-10-29:** `tests/cutscene_capture.gd` + `tools/cutscene_capture.sh` + `tools/make_contact_sheet.py` + `.github/workflows/cutscene-capture.yml` (manual dispatch, or on arena-branch pushes touching the crayon/proto views), documented in `docs/CUTSCENE_CAPTURE.md`. The workflow is new and has not yet had its first run — treat its first green run as the closing of this gap. Human/agent vision review then happens on the artifact/PR, which is also the taste gate no automation replaces. |
| Modify `.github/workflows/*` to add that job | ⚠️ token-dependent | The repo history records an automation account that could not write workflow files (hence the former `tools/ci/ci.yml`). If the agent's GitHub token lacks `workflow` scope, the workflow change must be landed by the owner or via `tools/ci/` staging; everything else (harness script, sheet builder) is ordinary repo content the agent can push. |
| Bake crayon sprites (`tools/bake_crayon.gd`) | ⚠️ same display caveat | Needs a display for `SubViewport` capture → same Xvfb CI job; import step is headless-safe. |
| Export a playable build | ⚠️ via CI, not wired | `export_presets.cfg` (Windows/Linux) exists; Actions would need the export-templates download (also GitHub Releases — fine on runners) added. Current CI tests but does not export. Not required to *develop* cutscenes. |
| Stack 2 external pre-render (Revideo/HyperFrames + Rough.js) | ⚠️ mostly | npm registry + GitHub are reachable from the sandbox (Node 22 present) and trivially from Actions. But: no `ffmpeg` in this sandbox (and Remotion's bundled ffmpeg can't encode Theora — a libtheora ffmpeg must come from an npm `@ffmpeg-installer`-style package or an Actions `apt`/setup step), and browser-based renderers download Chromium from non-GitHub CDNs (blocked here, fine on runners). Actuate it in CI, not in the sandbox. |
| Stack 3 Blender/Grease Pencil | ❌ not purely-GitHub from here | Blender binaries are distributed from blender.org, not GitHub (the GitHub repo is a source mirror; building it in CI is impractical). Actions could `apt install blender` from Ubuntu's archive — that's "CI with general internet", not "purely through GitHub". One more reason Blender stays an optional hero spike, not the backbone. |
| Human approval / taste judgement | ❌ by design | The owner rejected all five trailer cuts; no pipeline actuates *taste*. GitHub carries the loop (PR + contact-sheet artifacts + review), the human closes it. |

**Bottom line:** the recommended stack was (unintentionally) already shaped for repo-only actuation — presentation-only code, no binary assets, seeded determinism, text dialogue, MIT GitHub-native plugins, and a CI that already downloads its own engine. The one gap left is (2) possibly the workflow-push permission (the capture plumbing itself was added 2026-10-29; see `docs/CUTSCENE_CAPTURE.md`). Close those and the full loop — *agent writes beat → push → CI renders frames → review on PR → merge → (optionally) CI export* — runs without anyone opening an editor.
